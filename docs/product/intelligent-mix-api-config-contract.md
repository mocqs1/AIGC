# 智能混剪与模块化 API 配置契约

Status: proposed successor MVP contract  
Date: 2026-08-26  
Owner: AIGC Studio product/architecture

This document supersedes the settings and mix portions of
`docs/product/hermes-batch-mix-contract.md`. It is a product and API contract,
not an implementation recipe. Repository behavior and provider documentation
remain authoritative when they differ from this proposal.

## Product scope and naming

The user-facing operation currently called **素材混剪** is renamed to
**智能混剪**. The label must be updated in the composer, dialog title,
background-task strip, empty/error states, and accessibility names. Existing API
paths (`/api/mixes` and `/api/mixes/plan`) remain unchanged for compatibility.

智能混剪 has two stages:

1. An optional server-side Codex 5.6 Terra planner proposes an edit plan from
   the selected local/generated assets and the user's editing objective.
2. The local renderer validates that plan and executes it with FFmpeg. Terra
   never receives a filesystem path and never executes a command.

If Terra is unavailable, malformed, or disabled, the server produces a
deterministic local plan and the user may continue. A model outage must not
make local hard-cut rendering unavailable.

## UX contract

### API 配置窗口

The header settings action opens a modal titled **API 配置**. It contains a
module list or tabs; changing one module must not overwrite another module's
draft. Each module has:

- a human-readable name and a stable module id;
- API URL (HTTP or HTTPS, without embedded credentials);
- API key password field. Existing keys are represented only by
  `api_key_configured`; leaving the field empty preserves the key;
- model id and any provider-specific path/options;
- **Test connection**, **Save**, and **Cancel** actions;
- create/delete for custom modules that reuse a builtin protocol;
- a status indicator (`未配置`, `已配置`, `连接成功`, or `连接失败`).

Save and test requests go to the local AIGC API. The browser never calls a
configured upstream endpoint directly. Closing the modal keeps unsaved drafts
only until the modal is discarded; reopening loads the last persisted values.
Test failures are scoped to the selected module and do not clear a working
configuration.

The first release exposes these modules:

| Module id | UI name | Purpose | Default model/provider |
| --- | --- | --- | --- |
| `image.hermes` | Hermes 图片生成 | Text-to-image and image/reference reuse | `gpt-image-2` / Hermes gateway |
| `image.liblib` | Hermes 火山图片生成 | Independent second Hermes image configuration | `doubao-seedream-5-0-pro-260628` / Ark |
| `video.veo` | Google Veo 视频生成 | Existing text/image-to-video flow | Existing Veo model |
| `video.seedance` | Seedance 视频生成 | Existing Seedance flow | Existing Seedance text/image model |
| `mix.codex_terra` | Codex 5.6 Terra 智能规划 | Intelligent edit planning only | `gpt-5.6-terra` |

R2/storage credentials are not silently converted into this one-key schema;
they remain governed by their existing storage configuration until a separate
storage contract is approved.

### 智能混剪流程

1. The user opens **智能混剪** from the local media section.
2. They select two to fifty ordered image/video assets from the managed local
   library, set aspect ratio, image duration, optional video trims, target
   duration, and an editing objective (for example, “节奏紧凑，突出新品细节”).
3. The UI requests a plan preview. It shows planner (`Codex 5.6 Terra` or
   `本地规则`), ordered clips, trims/durations, transitions, total duration, and
   warnings before render.
4. The user can accept the plan or cancel. Accepting submits the validated plan
   to the mix job. A plan generated by Terra is never applied without server
   validation.
5. Progress is shown in the background task strip under the name **智能混剪**;
   success exposes preview/download, while source assets stay unchanged.

When Terra is not configured, the preview clearly says `本地规则` and explains
that the fallback is deterministic. A request may still explicitly choose the
local planner.

## Modular configuration API

### Registry and records

```text
GET    /api/settings/modules
POST   /api/settings/modules
GET    /api/settings/modules/{module_id}
PUT    /api/settings/modules/{module_id}
DELETE /api/settings/modules/{module_id}
POST   /api/settings/modules/{module_id}/test
POST   /api/settings/modules/{module_id}/models
POST   /api/settings/gateways/detect
```

Builtin `module_id` values are the table above. Custom modules use
`{category_prefix}.{slug}` (`image.`, `video.`, or `mix.`) and must copy a
builtin protocol. Unknown ids return 404. Builtin modules cannot be deleted.
The registry response is safe to render directly:

```json
{
  "modules": [
    {
      "id": "mix.codex_terra",
      "name": "Codex 5.6 Terra 智能规划",
      "category": "mix_planner",
      "api_url": "https://planner.example/v1/chat/completions",
      "model": "gpt-5.6-terra",
      "api_key_configured": true,
      "enabled": true,
      "capabilities": ["plan_mix"]
    }
  ]
}
```

The response never contains `api_key`, authorization headers, encrypted key
material, environment values, or absolute local paths. Provider-specific
options may be returned only after they have been classified as non-secret.

The write contract is:

```json
{
  "api_url": "https://planner.example/v1/chat/completions",
  "api_key": "new-key",
  "clear_api_key": false,
  "model": "gpt-5.6-terra",
  "enabled": true,
  "options": {}
}
```

`POST /api/settings/gateways/detect` takes a pasted `api_url`, write-only
`api_key`, optional `category`, and optional `model`. It matches a builtin
production protocol from host/model fingerprints, probes the provider catalog,
and returns a redacted `{ protocol, category, label, models, selected_model,
suggested_name, suggested_slug }` payload. Keys never appear in the response.

`POST /api/settings/modules` creates a custom module. `protocol` and `slug` are
optional: with a key the server detects the gateway; without a key it matches
the URL. The body is:

```json
{
  "name": "备用混剪规划",
  "category": "mix_planner",
  "protocol": "mix.codex_terra",
  "slug": "backup",
  "api_url": "https://planner.example/v1/chat/completions",
  "api_key": "new-key",
  "model": "gpt-5.6-terra",
  "enabled": true,
  "options": {}
}
```

A successful create returns `201` and the same redacted record as GET, with
`id` `{category_prefix}.{slug}`, `kind: "custom"`, and `protocol` equal to the
resolved builtin. Saving a custom module may switch `protocol` when the URL
now matches a different production gateway. `DELETE` returns `204` and is
rejected for builtin ids.
Custom image/video modules appear on `GET /api/providers` using the module id
as the public provider id. An enabled custom mix planner is preferred over
`mix.codex_terra`.

`api_key` is optional and write-only. An omitted or blank key preserves the
existing key unless `clear_api_key` is true. A successful write returns the
same redacted record as GET. `POST .../test` accepts the same draft shape but
does not persist it; it returns `{ "ok": true, "module_id": "..." }` or a
stable error code. Upstream response bodies are not copied into the error.

Recommended validation rules:

- URL is an absolute `http`/`https` URL with no username/password, fragment,
  or query credentials; reject malformed or overlong values.
- Model and path/options values are bounded strings and are module-allowlisted.
- Keys are bounded, trimmed, encrypted at rest, and never used as an
  idempotency key or log field.
- Updates are atomic. A failed write leaves the prior working record intact.
- Settings take effect for new jobs without a process restart; running jobs
  retain the resolved module snapshot used at enqueue time.

### Backwards-compatible Hermes migration

The existing endpoints remain supported:

```text
GET  /api/settings/hermes
PUT  /api/settings/hermes
POST /api/settings/hermes/test
```

They are compatibility aliases for `image.hermes`:

- GET preserves the old response shape (`api_url`, `model`, path fields, and
  `api_key_configured`) and never returns the key.
- PUT maps the old body to `PUT /api/settings/modules/image.hermes` and returns
  the old redacted shape. `clear_api_key` keeps its existing meaning.
- POST test maps to the modular test operation and does not persist a draft.
- If no modular record exists, the server lazily reads the existing persisted
  Hermes record and `HERMES_*` environment variables. The modular record wins
  once explicitly saved. Legacy files are not deleted or rewritten during a
  read; migration is atomic on the first modular write.
- Both old and new routes use the same encrypted secret store. Plaintext keys
  found in legacy files are ignored and must be re-entered by the user.

This allows an older web bundle to keep working while the new UI rolls out.
There is no reverse migration from other module ids into Hermes.

## Codex 5.6 Terra planning contract

### Planner request

The server calls the configured `mix.codex_terra` URL with an
OpenAI-compatible chat request. The browser calls only the local planning API:

```text
POST /api/mixes/plan
```

Request:

```json
{
  "clips": [
    { "asset_id": "imported/abc/a.png", "duration_ms": 3000 },
    { "asset_id": "videos/b.mp4", "start_ms": 0, "end_ms": 5000 }
  ],
  "objective": "节奏紧凑，突出新品细节",
  "target_duration_ms": 8000,
  "transition_mode": "auto",
  "planner": "codex_terra"
}
```

The server sends Terra only the objective, requested timing, media type, and
opaque asset ids. It may include safe duration/size metadata obtained locally;
it must not send absolute paths, raw file bytes, cookies, EXIF location data,
or other unrelated user content.

The OpenAI-compatible payload uses `model: "gpt-5.6-terra"`, temperature `0`,
and a JSON-object response format. The exact upstream chat path is configurable
per module. Authorization is added server-side as `Bearer <key>`.

### Planner response and validation

Terra must return a JSON object equivalent to:

```json
{
  "version": "aigc-mix-plan/v1",
  "planner": "codex_terra",
  "objective": "节奏紧凑，突出新品细节",
  "target_duration_ms": 8000,
  "clips": [
    {
      "asset_id": "imported/abc/a.png",
      "start_ms": 0,
      "duration_ms": 3000,
      "transition": "hard_cut"
    }
  ],
  "warnings": []
}
```

Before it is shown or queued, the server enforces:

- version `aigc-mix-plan/v1`, two to fifty clips, and a maximum total duration
  of five minutes;
- every `asset_id` is one of the user-selected assets and resolves inside the
  managed output roots;
- trim ranges are non-negative, ordered, and within the configured limits;
- durations are between 500 ms and 60 seconds per clip;
- transitions are renderer-supported. The current renderer supports
  `hard_cut`; a Terra `fade` suggestion is downgraded to hard cut with a
  visible warning until fade rendering is implemented;
- no shell command, URL, output path, codec flag, or arbitrary field from Terra
  is passed to FFmpeg.

Malformed or unsafe plans return a local fallback plan with a warning. The
fallback is deterministic and uses the selected order. `/api/mixes` accepts a
validated `plan` or `auto_plan: true`; it persists planner and warning metadata
with the job for reproducibility.

## Security and privacy rules

- Bind the local API to loopback by default. If remote access is enabled, add
  authentication and an outbound URL allowlist before exposing settings or
  planner calls.
- Reject URL credentials and validate outbound destinations to reduce SSRF.
  A deployment that permits localhost/private endpoints must make that an
  explicit operator setting, never a browser-controlled bypass.
- Store module keys server-side with Windows DPAPI (or the existing encrypted
  fallback on other platforms). Do not write plaintext keys to JSON, `.env`,
  browser storage, task records, telemetry, screenshots, or the knowledge
  vault.
- Redact `Authorization`, `api_key`, and provider error bodies in logs and
  user-facing errors. Do not include secrets in tracebacks returned by FastAPI.
- Resolve asset ids server-side and enforce canonical-path containment,
  extension/signature checks, size limits, and symlink/junction protection.
- Invoke FFmpeg with an argument array and fixed executable, never a shell
  string. Keep imported/generated source files immutable.
- Apply request, file-count, file-size, timeout, and planner rate limits. Do not
  send local media bytes to Terra merely to obtain an edit plan.

## Acceptance criteria

### Modular settings

- [ ] API 配置 lists every registered module and shows independent configured
      status; editing Terra does not modify Hermes or video modules.
- [ ] API URL, model, and non-secret options persist atomically and apply to
      newly submitted jobs without restart.
- [ ] Key input is masked, write-only, encrypted at rest, absent from GET/test
      responses, logs, browser storage, and error messages.
- [ ] Invalid URL/option values and upstream auth/timeouts produce stable,
      module-scoped errors while preserving the prior valid configuration.
- [ ] All three legacy Hermes routes pass compatibility tests and resolve to
      the same underlying `image.hermes` record.

### 智能混剪 and Terra

- [ ] Every user-facing occurrence of 素材混剪 is renamed 智能混剪; API paths
      remain compatible.
- [ ] User can preview a Terra or local plan, inspect order/timing/warnings,
      and explicitly accept it before rendering.
- [ ] Terra receives only the documented JSON metadata and is never called from
      the browser; its key is sent only in a server-side Authorization header.
- [ ] A malformed response, timeout, missing configuration, or disabled module
      selects the deterministic local plan and lets rendering continue.
- [ ] Plans cannot reference unselected assets, escape managed roots, exceed
      clip/total-duration limits, or inject FFmpeg options.
- [ ] Accepted plans and planner/warning metadata survive refresh/restart with
      the mix record; source assets remain byte-for-byte unchanged.
- [ ] A missing FFmpeg or invalid media fails before enqueueing with an
      actionable, secret-free message.
- [ ] Desktop and narrow mobile layouts have no horizontal overflow; dialog
      controls are keyboard reachable and expose meaningful accessible names.

## 已知 MVP 限制

- Terra support is an OpenAI-compatible planner adapter; model-specific
  extensions, streaming, and multi-agent editorial review are out of scope.
- The local renderer currently emits normalized MP4 with hard cuts and no
  audio track, beat matching, captions, transitions, or color grading.
- Terra does not inspect media pixels in this MVP. Rich visual understanding
  would require a separately approved media-analysis contract and privacy
  review.
- Module configuration is local to this AIGC Studio instance; there is no
  multi-user tenancy, role-based secret access, or remote secret manager.
- Legacy Hermes environment variables remain supported during migration and
  may be removed only in a later breaking release with a documented upgrade
  path.
